Maatilan Kirjanpitäjä

Problem

At the enterprise, production records, hourly work logs, and quality-control data were mostly kept on paper. All this information had to be manually transferred to the accounting program, making payroll calculations, production statistics tracking and planning complicated and time-consuming. Additionally, employee registration for company events was handled separately, also requiring manual processing.

Solution

We created a web-based application for farm production accounting, statistics tracking, reporting, and event registration. The application integrates with scales, label printers, QR code scanners, and it features a role-based access system for both management and employees. Salary-related data can be exported directly to the main accounting program.

Result

The application significantly accelerated and simplified enterprise accounting, increasing productivity through faster processing and real-time data analysis. Manual data entry was eliminated and real-time insights became available for better decision-making.

Technical Side

Oracle Database and APEX were deployed in a Docker container, with Nginx as a local proxy server and Cloudflare handling external traffic. The application was hosted on cloud infrastructure with a custom domain and utilized a dedicated SMTP server for notifications. A separate backup server ensured data reliability.

Customer

JSM Oy. Savonlinna, Finland.

BeeBooking

Problem

The company recruits seasonal workers from Finland and other countries, but the application process was inefficient and fragmented. Employees applied via email without a standardized application form or processing system. Each job application required an individual response, and employee data had to be manually transferred to the accounting system. When the employer organized transportation, passenger lists were made as spreadsheet, adding to the administrative burden.

Solution

We created a web platform for submitting job applications, processing them, and managing recruitment workflows. The system includes a ticket booking feature for employee transportation. Applicants can attach scans of required documents directly to their application forms, and they automatically receive a notification about the change in the processing status. Employee data can be exported to the accounting system.

Result

The application streamlined the entire recruitment process, handling over 500 job applications annually. Manual data entry and email-based communication were replaced with an efficient, centralized system that saves time and reduces errors.

Technical Side

Built on the same technical stack as Maatilan Kirjanpitäjä. The application features an improved UI/UX design and enhanced database architecture optimized for handling document attachments.

Customer

JSM Oy. Savonlinna, Finland.

Styres

Problem

Small businesses needing warehouse management systems face a challenging market situation. Enterprise-level ERP solutions with WMS modules cost 100+ euros monthly and offer far more complexity than needed. Simpler alternatives priced at 18-24 euros per month have significantly limited features or hidden event-based charges. Storage services like tire warehouses, service stations, or frozen berry storage facilities still rely on outdated methods such as spreadsheets due to the lack of affordable, targeted solutions.

Solution

We developed Styres, a modern SaaS warehouse management application designed specifically for small businesses. The platform provides essential modules including warehouse management, goods tracking, inventory control, customer management, and data import/export capabilities. The system features a simple, intuitive interface that delivers targeted information without unnecessary complexity. Optional modules for industry-specific features (such as tire storage services) allow for customization based on business needs.

Result

Styres delivers a targeted solution for small businesses seeking professional warehouse management without the burden of expensive, overcomplicated systems.

Technical Side

The architecture of the application supports horizontal scaling through multiple container instances and database schema separation for multi-tenant deployment. Cloud-hosted infrastructure. The web application supports QR and barcode scanning via the device camera and includes built-in label printer integration.

Customer

Autohuolto Kovanen Oy. Kerimäki, Finland.

SOP-Manager

Problem

The company's warehouse lacked an efficient system for locating components and tracking inventory. Workers spent unnecessary time searching for items, and real-time inventory monitoring was difficult. Although the company had an ERP system, it didn't provide dedicated tools for warehouse floor operations, slowing down production processes.

Solution

We developed SOP-Manager (Storage Order Pickup Manager), a web application that integrates directly with the company's existing ERP system and database. It helps workers locate components in the warehouse, manage item pickups, and monitor total inventory balances. It streamlines warehouse operations through user-created templates that organize and optimize material handling processes. Built as a standalone module, the application communicates directly with the organization's database without disrupting existing workflows.

Result

The application successfully enhanced warehouse efficiency by providing workers with quick access to location data and inventory information. Template-based workflows reduced the time needed for routine picking operations, and real-time inventory tracking improved production planning accuracy.

Technical Side

The system uses ODBC drivers (unixODBC, MySQL-connector) to establish database links with the client's MariaDB database. Oracle ORDS acts as a proxy server managing application connectivity. The architecture maintains security through firewall configuration while enabling direct communication between the application and the client's existing database infrastructure. Progressive Web App (PWA) technology allows installation on devices for quick access.

Customer

eLive Ecosystem Oy. Savonlinna, Finland.

Production Label Terminals

Problem

Production tracking at the enterprise required workers to manually record their output, leading to inconsistencies and wasted time. Employees needed a quick way to label manufactured products with tracking codes that would later be scanned in the warehouse for performance monitoring and inventory control.

Solution

We developed autonomous label printing terminals positioned directly at production workstations. Each terminal consists of a single-board computer (SBC) connected to a touchscreen display, RFID card reader, and label printer. Workers simply scan their personal RFID card containing their employee ID, enter the quantity of labels needed through the touch interface, and receive printed stickers immediately. The labeled products are later scanned in the warehouse, automatically recording both employee performance metrics and product tracking data.

Result

The terminals streamlined the production labeling process, eliminating manual recording and reducing workflow interruptions. Workers gained instant access to label printing at their workstations, while management received accurate and real-time data.

Technical Side

A single-board computer runs a custom application with a touchscreen interface. System integrated with RFID card readers for employee identification and thermal label printers for sticker output. The terminals operate within the network communicating with the database to log production data.

Customer

JSM Oy. Savonlinna, Finland.

Energy Measurement System

Problem

Measuring electrical power, energy, and temperature in real time required a compact system with reliable sensor monitoring and safety protection. The system also needed to detect temperature and sensor faults to prevent overheating.

Solution

Developed an energy measurement system that continuously measures voltage, current, power, cumulative energy, and temperature. A safety relay automatically disconnects the heating element when configured temperature limits or sensor fault conditions are detected.

Result

The system provides real-time telemetry through a USB virtual COM port and can visualize and save measurement data using Serial Studio. It also supports configurable temperature limits, hysteresis, calibration offsets, and console commands.

Technical Side

The system is based on an ESP32-S3, INA228 power monitor, MAX31865 RTD amplifier, Pt1000 temperature sensor, safety relay, and fuse. Communication uses UART, with CSV telemetry transmitted every second.

Customer

Electronics 3K Factory, Kaakkois-Suomen Ammattikorkeakoulu Oy. Savonlinna Finland.

Sensor Simulator

Problem

Testing systems with rotational sensors requires a reliable way to generate sensor signals at different RPM values. Using real sensors for every test can make development and debugging more difficult and less flexible.

Solution

Developed a Python application that simulates four independent rotational sensors through GPIO pins (Raspberry Pi or compatible board). The application supports automatic and manual RPM modes, individual sensor pause/resume control, and reusable configurations.

Result

The simulator provides a flexible tool for testing systems with different sensor speeds without requiring physical rotational sensors. Configuration data is stored locally, validated at startup, and simulation and configuration events are recorded in a console log.

Technical Side

The application was developed in Python with a PySide6 graphical user interface. It controls four GPIO outputs, generates signals based on RPM settings, and stores configurations in a local settings.json file.

Customer

Electronics 3K Factory, Kaakkois-Suomen Ammattikorkeakoulu Oy. Savonlinna Finland.

AI Tools

Problem

Many AI tools require cloud services, which can limit privacy, control, and offline use. I wanted to explore how local AI models could be used for everyday chat, document-based tasks, and automated news monitoring.

Solution

Developed several local AI applications using Ollama, including a simple terminal chat, a tool-using local agent, and a news monitoring agent. The local agent can search documents and use custom tools, while the news agent collects RSS articles, filters them by keywords, and generates summaries.

Result

The projects demonstrate practical ways to build AI applications that run locally without relying on external AI APIs. The agent can combine an LLM with external tools and local documents, not only using the model's built-in knowledge. This provides a foundation for building more practical private AI assistants. The news monitoring system can automatically identify relevant articles and prepare structured reports from them.

Technical Side

The applications were developed in Python using Ollama for local LLM inference. The local agent uses LlamaIndex with Hugging Face embeddings, vector search and BM25 hybrid retrieval, while the news monitoring agent uses RSS scraping, LLM-based filtering and summarization, JSON storage, and email notifications.

ML Model Training and Using in Embedded Systems

Problem

Snowfall is difficult to predict using only simple temperature and humidity thresholds. The project aimed to create a lightweight prediction model that could run directly on a small embedded device.

Solution

I trained a machine learning model using 10 years of historical weather data from the Savonlinna region in Finland. The model used temperature and humidity measurements from the previous three hours to predict whether snow was expected.

Result

The trained model was converted to TensorFlow Lite and deployed on an ESP32. The ESP32 reads data from a temperature and humidity sensor and performs snow prediction locally without needing a cloud connection.

Technical Side

The model was developed and trained with Python, Pandas, Scikit-learn, and TensorFlow using a small neural network. The model was quantized to INT8 and integrated into an ESP32 application using TensorFlow Lite for Microcontrollers and ESP-IDF.

REST API

Problem

Some web applications need a simple way to access data stored in a database located on a remote server or in a separate container.

Solution

I developed a REST API that connects PostgreSQL with Oracle APEX web application. The API provides endpoints for creating, reading, updating, and deleting user data, with input validation and database error handling.

Result

Oracle APEX was successfully connected to the PostgreSQL database through the API. The same API can also be used by other applications that need to work with the separate database.

Technical Side

The API was developed with Python (FastAPI, Pydantic, SQLAlchemy libraries). The application was containerized with Docker Compose together with PostgreSQL and Oracle XE, using a shared Docker network. Oracle APEX was configured to use the API as a REST Data Source.
